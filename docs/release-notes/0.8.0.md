## webForCore-thirdparty 0.8.0

- **`webForCore.AutoMapperLegacy`: C# 14 only where 3.x's `ResolutionContext` members are used, and what C# 14 changes**
  (#14). The README said every project using the facade needs C# 14. Only `SourceValue`, `DestinationValue`, `Options`
  and the context's other 3.x members do (they are extension properties, and AutoMapper 12's `ResolutionContext` is
  sealed); the rest of the facade works on C# 13, which a new test project checks. The README now also says that C# 14
  makes `array.Contains` in an expression tree a `MemoryExtensions.Contains` call over a span (webForCore#138), which
  EF 6, LINQ to SQL and an application's own visitors don't know, with the two workarounds (a cast to
  `IEnumerable<T>`, or a visitor that maps the call back, both tested), and that in Umbraco 7 only Umbraco.Web needs
  C# 14: Umbraco.Core's `ExpressionVisitorBase` failed saving content when Umbraco.Core was on C# 14 (webForCore smoke
  test F165).
