## webForCore-thirdparty 0.7.0

- **`webForCore.AutoMapperLegacy`: a member given a value of its own type is assigned it, as AutoMapper 3.x did**
  (#11). AutoMapper 12-14 look for a map along the destination's base types too, so a member mapped from a list of
  values that already had its element type (Umbraco 7.15's `PropertyGroupDisplay<MemberPropertyTypeDisplay>.Properties`)
  went through the base type's map: on AutoMapper 12 building the configuration threw, so every `Mapper.Map` failed and
  Umbraco's installer couldn't finish; on 13 and 14 mapping the member threw `NotSupportedException`. Umbraco 7 no
  longer needs its `Ignore()` and `AfterMap` workaround (webForCore smoke test F104).
- **Built against webForCore 0.9.0**, whose assemblies have Microsoft's identities (webForCore #141): AjaxControlToolkit
  now references `System.Web.Extensions` 4.0.0.0 (`31bf3856ad364e35`), as the original package did; built against
  0.8.0 it would have referenced 11.0.0.0, which webForCore 0.9.0 no longer has.

Built and tested against webForCore 0.9.0 and drawingForCore 0.3.0.
