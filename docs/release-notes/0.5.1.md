## webForCore-thirdparty 0.5.1

- **New: `webForCore.AutoMapperLegacy`** (#9). AutoMapper 3.x and 4.x's static API (`Mapper.CreateMap`, `Mapper.Map`,
  `Profile.Configure`, `ValueResolver<,>`, `TypeConverter<,>`, `ResolveUsing`, `Project().To<T>()`, ...) on top of
  AutoMapper 12-14, so that applications written against it recompile on .NET with their mapping code unchanged.
  - AutoMapper before 12 doesn't run on .NET: configuring a map throws while it scans `System.Linq.Enumerable`'s
    methods (webForCore smoke test F22). Found migrating SocialGoal (AutoMapper 3.1) and Umbraco 7.15 (3.3.1).
  - A compatibility package, not a replacement: its own assembly and namespace (`AutoMapperLegacy`), and a dependency
    on AutoMapper `[12.0.1, 15)`. Replace the AutoMapper 3.x/4.x package with it and add
    `global using AutoMapperLegacy;`, `global using Mapper = AutoMapperLegacy.Mapper;` and, for 3.x profiles,
    `global using Profile = AutoMapperLegacy.Profile;`. Its README lists what else may need a change and where it
    behaves differently from 3.x.
  - AutoMapper 12-14 carry GHSA-rvv3-g6hj-g44x (deep-recursion denial of service; 3.x and 4.x have it too), which
    NuGet audit reports. AutoMapper 15 and later aren't MIT, so the range stops before 15.
  - Its tests include AutoMapper 3.3.1's own unit tests, ported; they run with AutoMapper 12.0.1 and 14.0.0.
- CONTRIBUTING.md: a library is here because applications need it to migrate, and compatibility packages such as this
  one have their own identity.

Built and tested against webForCore 0.7.0 and drawingForCore 0.2.0.
